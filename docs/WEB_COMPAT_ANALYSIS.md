# 웹(HTML5) 호환성 분석 — V3.0.4

> **방법:** 소스(21,501줄)를 grep 으로 훑은 **정적 분석**입니다. 이 환경에는 Godot 가 없어 웹 내보내기·실행은 **0회**입니다. 아래 "웹에서 될 것"은 예상일 뿐 확인된 사실이 아닙니다.

## 1. 요약
| 항목 | 결과 | 근거 |
|---|---|---|
| 렌더러 전환 필요? | **불필요** — 이미 `gl_compatibility` | `project.godot` `rendering_method="gl_compatibility"` (웹은 호환성 렌더러만 지원) |
| 스레드 사용 | 없음 | `Thread/Mutex/WorkerThreadPool` 0건 → 스레드 없는 웹 빌드(`thread_support=false`)로 충분. 서버 특수 헤더 불필요 |
| 외부 프로그램/OS 호출 | 없음 | `OS.execute/shell_open` 등 0건 |
| 외부 에셋 | 없음 | `assets/` 폴더 없음, 텍스처·모델·글꼴 전부 코드로 생성 → `.pck` 는 작고 로딩 병목은 `.wasm`(약 40MB) |
| 저장 | 가능성 높음 | `user://` 는 웹에서 브라우저 저장소(IndexedDB)로 매핑. 저장 함수에는 이름바꾸기 실패 시 직접 쓰기 대비가 이미 있음 |
| 소리 | **위험** | `AudioStreamGenerator`(코드 합성). 아래 3-A |
| 터치 | 가능성 높음 | 입력은 `InputEventScreenTouch/Drag` 기반이라 브라우저 터치와 같은 경로. 아래 4 |
| 성능 | **가장 큰 위험** | 건물·NPC·차량이 많은 3D, 웹은 스레드 없음. 아래 5 |

## 2. 렌더러
- 이미 호환성 렌더러라 **전환 작업 없음**. Environment 의 안개·톤매핑·조정(adjustment)은 호환성 렌더러에서도 지원되는 기능으로 알고 있으나 **웹에서의 모습은 미확인**.
- `project.godot` 의 `config/features` 에 "4.3" 이 적혀 있음(4.7.2 에서 열면 에디터가 갱신할 수 있음, 동작 영향 없음으로 추정).

## 3. 웹에서 문제가 될 수 있는 기능
### A. 합성 배경음/사이렌 (`scripts/v22/v22_audio.gd`)
- 매 프레임 `push_frame` 으로 11,025Hz 소리를 직접 채움. 한 프레임에 최대 900샘플만 채우도록 제한돼 있어서 **프레임이 약 12fps 아래로 떨어지면 소리가 끊길 수 있음**(웹은 스레드가 없어 더 쉽게 끊길 가능성).
- 브라우저는 **첫 터치 전에는 소리를 허용하지 않음**. Godot 가 처리하지만 아이폰에서의 동작은 미확인.
- 대응: 소리가 거슬리면 `feature_flags.gd` 의 `V22_AUDIO=false`. 코드는 건드리지 않음(성능을 이유로 한 재작성은 보류).

### B. 저장 (`user://`)
- 브라우저의 "사이트 데이터 삭제", 사파리의 **비공개 모드**, 아이폰의 7일 미사용 정리 등으로 저장이 사라질 수 있음. 게임 코드로는 막을 수 없는 부분.
- 저장이 IndexedDB 에 실제로 반영되는 시점(앱 종료 직전 등)은 미확인. **친구에게 "저장 후 바로 탭을 닫지 말고 몇 초 기다리기" 안내 권장.**

### C. 자체 점검 (`V23_SELFTEST`)
- 시작 때 `user://v22_selftest.txt` 에 쓰는 기능. 웹에서도 쓰기만 되면 문제 없음. 점검 결과 문구는 화면 위쪽에 잠시 뜸 → 친구가 스크린샷으로 보내면 유용.

### D. 시작 시 작업량
- 도시/텍스처를 시작할 때 코드로 생성(`ImageTexture/Image.create` 계열 48곳). 스레드 없는 웹에서는 이 구간에 **화면이 멈춘 것처럼 보일 수 있음**(브라우저가 "응답 없음"을 띄울 수도 있음). 실제 길이는 미측정.

### E. 이상 없다고 본 것 (정적 분석 기준)
`DisplayServer`, `Input.vibrate`, 마우스 모드, 가속도/자이로, `get_tree().quit()`, `ResourceLoader.load_threaded`, GDExtension, `WorkerThreadPool` 모두 사용 0건.

## 4. 터치 UI / 해상도
- `window/size` 1280×720, `stretch mode=canvas_items`, `aspect=expand` → 화면 비율이 달라도 가로 방향에서는 UI 가 화면 가장자리(`s.x-130` 등 상대 좌표)에 붙음. 가로 폰(예: 844×390, 2.16:1)에서 버튼 위치·크기가 적절한지는 **실제 폰에서 미확인**.
- **세로 화면:** 앱의 `orientation=4`(가로 고정)는 웹에서 작동하지 않음. 아이폰 사파리는 웹에서 방향 잠금을 지원하지 않는 것으로 알고 있음 → 내보내기 설정의 `head_include` 로 **세로일 때 "폰을 가로로 눕혀 주세요" 검은 안내**가 화면을 덮도록 함(CSS 만 사용, 미검증).
- `pointing/emulate_touch_from_mouse=true`: PC 브라우저에서 마우스로 시험하는 데 도움. 폰에서 터치와 마우스 이벤트가 중복될 위험은 낮다고 보지만 **미확인** — 이동/버튼이 두 번 눌리는 증상이 있으면 알려 주세요.
- 아이폰 사파리: 전체화면 API 가 막혀 주소창이 남을 수 있음. "홈 화면에 추가"로 전체화면처럼 쓰는 방법(PWA)은 내보내기 옵션이 있으나 이번에는 **켜지 않음**(서비스워커 캐시로 옛 버전이 남는 위험을 아직 검증하지 못함).

## 5. 성능 (웹 최적화)
이번 버전에서 한 일(모두 미측정):
1. **웹 첫 실행 한정 저사양 기본값** (`scripts/v1/game_settings.gd`, `OS.has_feature("web")` 일 때만): 그래픽 품질 0, 그림자 끔, 시민 4명, 차량 4대, 시야 거리 "보통", 경찰 최대 3. 설정 화면에서 바꾸면 그 값이 우선. 앱/PC 동작은 같음(웹 분기만 추가).
2. 스레드 없는 빌드, 모바일/데스크톱 텍스처 압축 모두 켬(텍스처가 거의 코드 생성이라 영향은 작음).
3. 이미 있던 최적화 유지: MultiMesh 묶음 그리기, 그림자 제한, 시야 거리 설정, 저사양 모드.

하지 않은 것(이유): 코드 대규모 재작성 금지 규칙, 측정 도구 없음. 프레임 수치는 모두 폰에서 화면 왼쪽 위 `FPS` 표시로 확인해야 함.

## 6. 웹 빌드 가능 여부 / 대안
- **가능 여부:** 원리상 가능. 소스에서 막는 요소는 발견하지 못함. 그러나 **내보내기 성공 여부 자체가 미확인**.
- **너무 느린 경우의 대안(순서대로):** ① 설정 > 저사양 ② `CROWD_COUNT=0`, `V22_AUDIO=false`, `V3_BUILD=false` ③ 그래도 폰에서 5fps 수준이면 웹은 포기하고 안드로이드 APK(PC 필요) / 아이폰은 맥+TestFlight 경로.
