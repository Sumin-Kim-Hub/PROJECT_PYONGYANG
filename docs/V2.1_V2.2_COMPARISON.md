# V2.1 ↔ V2.2 ↔ V2.3 구조 비교

> 이 비교는 파일 내용을 `diff` 로 직접 대조한 정적 비교입니다. 세 버전 모두 Godot 에서 실행해 본 적이 없습니다 (V2.1 은 사용자가 "이동 불가" 보고 후 수정본이며 실행 확인은 사용자 몫).

|---|---|---|---|
| .gd 파일 수 | 51 | 60 | 63 |

## 3. V2.2 → V2.3 에서 바뀐 기존 파일 (5개)
`v22/pass_system.gd`(`_allow` 의 주 임무 갱신을 north/base 로 제한), `v22/v22_manager.gd`(v23·selftest 후크), `data/feature_flags.gd`(+2), `data/item_data.gd`(+3), `data/quest_data.gd`(+1). 허브(`interaction_system.gd`)는 V2.3 에서 건드리지 않았습니다.

## 4. 연결 구조 (V2.2/V2.3)
```
main.gd (보호)
  └ interaction_system.gd (허브)
       ├ v1_manager / v2_manager / gfx_manager / interior_manager ... (V2.1 과 동일)
       └ v22_manager.gd  ← 허브의 유일한 V2.2 창구 (feature flag ENABLE_V22)
            ├ pass_system.gd      통행증·검문소 (north, base, + leader)
            ├ npc_social.gd       NPC 설득/위협/뇌물/부탁/거래/정보
            ├ v22_world.gd        새 지역 8곳, 경계 벽 이동, NPC 배치, 거리별 숨김
            ├ v22_interiors.gd    슬롯 10·11·12
            ├ v23_leader.gd       (V2.3) 청사 구역 + 슬롯 13·14 + 임무 q_v23_leader
            ├ v23_selftest.gd     (V2.3) 자체 점검
            └ v22_audio.gd        합성 배경음, 방송 신호음, 사이렌
```
- 각 모듈은 `load()` + `can_instantiate()` 로 불러오고, 실패해도 게임은 계속됩니다. 만들기가 끝나길 기다리는 `_wait_flag` 는 시간 제한이 있어 모듈 오류로 멈추지 않습니다.
- 기능 스위치를 끄는 순서(문제 시): `V23_SELFTEST` → `V23_LEADER` → `V22_AUDIO` → `V22_WORLD` → `ENABLE_V22`(= V2.1 상태).

## 5. 위험이 가장 큰 곳 (실행 전 추정)
1. 허브 `_teleport` 후크 (모든 출입에 영향) — 실패하면 이동 자체가 이상해질 수 있음
2. 경계 벽 이동 (`_boundary`) — 벽을 못 찾으면 새 지역에 못 감
3. `v22_world.build` / `v22_interiors.build` 의 한 프레임씩 나눠 만들기 — 느린 폰에서 시작이 길어질 수 있음
4. 새 NPC 28 + 6명(순찰/경비 포함)의 물리 처리 — 거리 기반 정지로 줄였지만 측정은 못 함
